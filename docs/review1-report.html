1.Module Requirements

The project studies a failure in agentic retrieval systems. When a system writes its own follow up search queries using what it currently believes, and the retriever ranks documents by how closely they match the wording of that query, the system can collect progressively more one sided evidence without any document being false.

Review One covers the first functional module, which is the retrieval and measurement module. Its requirements are listed below.

Functional requirements

IDRequirementAcceptance condition
FR-1Load a benchmark whose evidence balance is guaranteed by construction Every contested question carries an equal number of supporting and opposing passages
FR-2Encode any text into a vector using one shared vocabulary Encoding is deterministic and out of vocabulary text does not crash the pipeline
FR-3Retrieve the top k passages for a query, ranked by wording similarity Exactly k results, ordered by descending score, with no mutation of the corpus
FR-4Compute the BAQD drift score at every hop Three embeddings and two cosine similarities, returning zero when the belief is empty
FR-5Measure the balance of each retrieved set Skew in the range minus one to plus one, with an empty set handled safely
FR-6Log every retrieval as a reproducible trace One row per retrieval carrying the query, the score and the retrieved passages

Non functional requirements

IDRequirementReason
NFR-1No GPU, no paid API, no model download The work must be reproducible on ordinary student hardware
NFR-2The metric must run in milliseconds A costly detector stays in a paper, a cheap one can run inside a live system
NFR-3Every published number must be regenerated from the log Results are verified by machine rather than asserted by hand

2.Design Phase: Use Case Diagram

Three actors interact with the system. The researcher runs experiments and inspects traces. The continuous integration pipeline reruns everything automatically on each push, which is what keeps the published numbers honest. The review panel views the generated results.

The separation matters for this project. Running the drift experiment always includes encoding, scoring and retrieval, so those are modelled as included sub functions rather than as separate things an actor would call. Validating corpus integrity is reachable on its own because the continuous integration pipeline runs it as a standalone check.

3.Design Phase: Activity Diagram

The experiment is a triple nested loop over questions, arms and hops. The important detail is the step that sets the belief to whatever was just read, because that is the step which closes the loop the project is studying.

4.Design Phase: Flowchart of the Metric

This is the core computation, shown at statement level. It is deliberately small. Three encodings, one guard against an empty belief vector, two cosine similarities and a subtraction.

Why the guard matters. At the first hop the belief has not yet been formed, so the belief vector can be empty. Without the guard the cosine would divide by zero. Test case TC-09 pins this behaviour.

Result. On a corpus balanced by construction, an oracle query built only from vocabulary unique to one side retrieves every supporting passage, and the reverse oracle retrieves every opposing passage. Query wording alone moves retrieved evidence across the full range of 2.00. This is the half of the loop the module set out to test, and it holds.
Reported honestly. The drift arm was no better than the neutral arm and the metric stayed flat, so the gate test returned a null result. The diagnostic locates the cause in the lexical encoder and in queries that were too mild, not in the mechanism. The experiment was not adjusted until it agreed with the hypothesis.

7.Testing Approach

Testing ran alongside implementation rather than after it. Every module was exercised with valid input, boundary input and invalid input as it was written. Where the output did not match the expectation, the case was recorded as a failure, the defect was fixed, and the same case was run again and recorded as a pass.

Categories covered

  • Unit tests on the metric, covering identical, orthogonal, opposite and zero vectors.
  • Boundary tests on the retriever, covering k of zero, negative k and k larger than the corpus.
  • Integrity tests on the benchmark, enforcing that balance is genuinely guaranteed.
  • Regression tests that pin defects already found, so they cannot return silently.
  • End to end invariants on the published numbers, such as the trace row count.

TC-38Encoder fitted on one question's 8 passages, then asked to encode a query using vocabulary from another questionA usable vector, so ranking still works across the collectionAll zero vector, so every passage scored 0.0 and ranking was noiseFAILInverse document frequency was computed over 8 documents. The first experiment run produced meaningless balance figures
TC-38-R1Same query after fitting the encoder over the whole collectionA non zero vectorNon zero vector, ranking restoredPASSrun_experiment.py now fits one encoder over every passage and query before the loop. Defect resolved, pinned by this test
How to read TC-36. A negative k was passed to the retriever. Python interprets scored[:-1] as everything except the last item, so instead of returning nothing the retriever silently returned the seven worst ranked passages. A guard for k of zero or less fixed it, and the retest passes.

Next steps

ChangeWhy, from this phase's evidence Expected effect
Dense encoder The drift score moved the wrong way because short queries share few literal words with long belief text. A lexical encoder measures vocabulary overlap, not meaning. The metric registers belief alignment rather than word overlap
Live agent Our authored probes captured only 4.2 percent of the available range. Answers the real gate question for the first time
Larger benchmark Six contested questions and a top k of four make every measurement coarse. Enough resolution to separate a real effect from noise
Known limitations. The passages are synthetic research style text written for this prototype, not quotations from real papers. The benchmark is small. The queries are authored probes rather than model output. These are stated so the results are not read as more than they are.
