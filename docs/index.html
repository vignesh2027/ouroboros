Ouroboros

Detecting self-confirming retrieval loops in agentic RAG. The serpent that eats its own tail.

SPIRAL-Bench on Hugging Face Source code Reproduce in two commands

The problem

An agentic RAG system searches several times, and it writes each follow-up query itself, using what it currently believes. A retriever ranks documents by how closely they match the wording of the query it receives.

Put those two facts together and a loop closes. Belief shapes the query, the query shapes the evidence, and the evidence hardens the belief. The opposing studies are never deleted. They are simply never asked for again.

The dangerous part is that nothing false is ever produced. Every retrieved document is authentic, every citation checks out, and a faithfulness scorer rates the answer as fully faithful. It is a sampling failure, not a truth failure, which is why existing safeguards cannot see it. They all read the answer. None of them read the query.

What we measured

2.00

The full range of retrieved evidence that query wording alone can reach, from every document supporting to every document opposing.

4.2%

The share of that range our first hand-written drift queries captured.

12.9%

Vocabulary shared between supporting and opposing passages, so stance is separable in principle.

The finding. Query wording alone controls which evidence comes back. That is the half of the loop this experiment set out to test, and it holds on a corpus we verified is balanced.
What it does not show. The queries in v0 were written by us, not by a language model. Whether a live agent drifts far enough to trigger the effect is the open question, and the next experiment answers it.

The metric

BAQD, or Belief-Aligned Query Drift, asks one question at every hop: is the query the system just wrote closer to what it already believes than the user's neutral question was?

BAQD(n) = cos(query_n, belief_n-1) - cos(question_0, belief_n-1)

Three embeddings, two cosine similarities, one subtraction. No training, no labelled data and no GPU. It runs in milliseconds on a laptop, which is the point: a costly detector stays in a paper, while one this cheap can run inside a live system.

The benchmark

SPIRAL-Bench v0 exists because testing this claim needs a corpus where balance is guaranteed rather than assumed. Every contested question carries exactly four supporting and four opposing passages.

ConfigRowsWhat it holds
passages64Contested questions balanced 4 / 4, plus settled questions as a one-sided control
queries48Two arms per question, drift and neutral, three hops each
traces48Logged experiment output, one row per retrieval

Open the dataset on Hugging Face. The passages are synthetic research-style text written for this prototype. They describe real findings in outline but they are not quotations and must not be cited as literature.

Reproduce

No GPU, no API key, no model download. Requires numpy, scikit-learn and matplotlib.

git clone https://github.com/vignesh2027/ouroboros
cd ouroboros
pip install -r requirements.txt

python3 run_experiment.py    # 48 retrievals, drift arm versus neutral arm
python3 run_diagnostic.py    # locates the cause of the null result
python3 make_chart.py        # rebuilds the figure above

Continuous integration runs both experiments on every push, so the numbers on this page are checked automatically rather than asserted.
